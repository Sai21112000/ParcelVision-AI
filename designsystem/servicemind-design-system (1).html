ServiceMind Design System

This is not a reinterpretation of ServiceMind — it is ServiceMind's own design system, lifted out of the running application. The app already ships a complete internal system in styles-VWA5PDVG.css: 48 semantic colour tokens and 289 tis-* component classes. Section 3 of this file is that stylesheet's tis-* rules byte-for-byte, so anything you build from these snippets is pixel-identical to production by construction.

Every example below renders with the real class names Angular Material emits, which means you can copy any snippet straight into the Angular codebase and it will inherit the app's own styling with no changes.

Colour tokens

The palette is declared once on body and consumed everywhere through var(--tis-*). Nothing in the component layer hardcodes a brand colour, which is why the theme switcher in the toolbar re-skins this entire page instantly. Swatches below read their value live from the cascade, so switching themes shows you the real resolved colour.

warning_amber
Three tokens are referenced but never declared in the shipped admin bundle: --tis-heading-color (used by .tis-h1–.tis-h6), --tis-gray-bg and --tis-icon. In production they resolve to nothing, so .tis-h1 silently inherits its colour. This file declares them with the values the console actually renders — see the Documented additions comment in section 1.

Theming

ServiceMind ships three skins. Critically, the tenant theme overrides the same token names rather than introducing new ones — so re-skinning a whole application is a six-value change, and any component you build on these tokens is themeable for free.

ThemeWhere it appliesHow it is setPrimary
Admin console Everything under /admin/* — the back-office this system was extracted from. Static, in the body block of the global stylesheet. #3838a2 indigo
Tenant & Engineer The resident and field-technician apps. Per-organisation, from Organisation Setup › Theme. Six pickers write --tis-primary, --tis-secondary, --tis-danger, --tis-success, --tis-accent and --tis-icon. #1d4bac blue
Legacy portal The pre-login shell and older tenant portal screens. A parallel --tis-*-bg-color / --tis-*-text-color family injected inline onto <html>, with per-region groups for header, dashboard, account, sidebar and notifications. #c32124 crimson

Re-skinning an organisation

The complete override the Theme Setup screen produces. Nothing else is needed.

body,
[data-theme="tenant"] {
  --tis-primary:   #1d4bac;  /* buttons, links, active states, tab underline */
  --tis-secondary: #fbc5d4;  /* muted fills, light chips              */
  --tis-danger:    #f52768;  /* destructive actions, cancel           */
  --tis-success:   #4dae50;  /* confirmations, completed states       */
  --tis-accent:    #d9f1ff;  /* expanders, highlight surfaces         */
  --tis-icon:      #434343;  /* default icon colour                   */
}
lightbulb
When you add a component, style it with var(--tis-primary) rather than #3838a2. It then themes correctly in all three skins with no extra work — this is the single most important convention in the codebase.

Typography

Roboto for Latin, Prompt and TH Sarabun PSK for Thai — ServiceMind is a bilingual product and Thai copy appears throughout real records, so both stacks matter. Body text is 16px/24px; dense surfaces (tables, badges, paginator) step down to 14px and 12px.

Space, radius & elevation

ServiceMind uses a 5px-based rhythm rather than the 4/8 grid you might expect: 5, 10, 15 and 20px are the load-bearing values, with Material's 16/24px showing through on components Material owns (dialogs, cards, form fields). Worth knowing before you add spacing that looks almost-right.
